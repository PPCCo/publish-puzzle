# Claude Puzzle & Printable Publishing House

A repository-native, file-based publishing company for Claude Code that produces
puzzle books, activity books, coloring books, guided journals, workbooks, planners,
and digital printables. It coordinates specialist Claude Opus 4.8 agents to discover,
plan, generate, verify, illustrate, lay out, validate, package, and maintain products
without requiring PostgreSQL, Temporal, Redis, Kubernetes, or the Claude Agent SDK.

The governing principle: **content is generated by code and independently verified by
code.** A generator never signs off its own solvability, uniqueness, answer-key, or
difficulty claims — a separate code-backed verifier does. Coloring line art is
**original only**. Humans approve at six defined gates.

## 1. Operating model

The repository is the system of record:

- `.claude/` defines company policy, agents, skills, workflows, hooks, standards, schemas, templates, and deterministic scripts.
- `projects/<project-id>/` contains one self-contained product project.
- `series/<series-id>/series.yaml` groups products that ship together; each product keeps its own state, approvals, freezes, and release gates.
- `catalog/products.json` indexes projects; it is not a source of truth for content.
- Project state is stored in `state.json`; immutable events are appended to `events.ndjson`.
- Artifacts are hashed with SHA-256 and registered in `artifacts/manifest.json`.
- Human approvals bind an approver and scope to exact artifact hashes.
- External publication is disabled by default. The distribution workflow produces upload-ready channel packages only.

## 2. Product families

- **Puzzle & activity books** — deterministically generated and independently code-verified (uniqueness, solvability, answer keys, difficulty).
- **Coloring books** — original AI line-art only; no tracing and no imitation of named living artists.
- **Guided journals, workbooks, & planners** — prompts and templates matched to the audience reading level and page-space targets.
- **Digital printables & templates** — print-at-home PDFs at stated DPI and US Letter / A4 for Etsy/Gumroad/generic delivery.

Formats: paperback, hardcover, digital-pdf. Channels: KDP, Etsy, Gumroad, generic.

## 4. Installation

```bash

python3 -m venv .venv

python -m unittest discover -s tests -v
```

Review `.claude/settings.json`, `.claude/hooks/`, and `.mcp.json` before accepting Claude Code workspace trust.

## 5. Start Claude Code

```bash
claude --agent publisher-in-chief --model "@bedrock-eus2/us.anthropic.claude-opus-4-8" --effort xhigh
```

Then run:

```text
/product-doctor
/product-new "Large-print sudoku for seniors" --audience senior-large-print --type puzzle-book --formats paperback
/product-status <project-id>
/product-run <project-id> --until human-gate --max-stages 3
/product-resume <project-id>
```

`/product-run` advances validated stages until its configured stage limit, a blocker, or the next human gate. Skills beginning with `product-approve-`, `product-freeze`, `product-release-authorize`, and `product-submit` are human-only. Claude cannot invoke them autonomously.

## 6. Canonical lifecycle

```text
DISCOVERY
-> NICHE_ASSESSMENT
-> NICHE_APPROVAL                    # human gate
-> PLANNING
-> CONTENT_GENERATION                # code generates
-> CONTENT_VERIFICATION              # code verifies, independently
-> INTERIOR_APPROVAL                 # human gate; freezes verified batches
-> VISUAL_DEVELOPMENT
-> COVER_APPROVAL                    # human gate
-> LAYOUT_AND_FORMAT_BUILD
-> ACCESSIBILITY_VALIDATION
-> RIGHTS_CLEARANCE
-> COMPLIANCE_APPROVAL               # human gate
-> METADATA_AND_COMMERCIAL_PACKAGE
-> LISTING_APPROVAL                  # human gate
-> FINAL_PROOF
-> PLATFORM_PACKAGING
-> RELEASE_AUTHORIZATION             # human gate; two approvers
-> READY_FOR_SUBMISSION
-> SUBMISSION                        # records human/platform activity
-> PUBLISHED
-> MONITORING
-> EDITION_MAINTENANCE
```

The deterministic state script controls transitions. Agents may recommend a transition but may not bypass a gate.

## 8. Core CLI

```bash
# Environment and framework
python3 .claude/scripts/ph_cli.py doctor
python3 .claude/scripts/ph_cli.py framework validate

# Projects
python3 .claude/scripts/ph_cli.py project init --topic "..." --audience senior-large-print --product-type puzzle-book --formats paperback
python3 .claude/scripts/ph_cli.py project list
python3 .claude/scripts/ph_cli.py project status <id>
python3 .claude/scripts/ph_cli.py project plan <id>
python3 .claude/scripts/ph_cli.py project transition <id> --to PLANNING --actor human --reason "Niche approved"

# Content: code generates, code verifies (independently)
python3 .claude/scripts/ph_cli.py generate <id> --type sudoku --count 30 --difficulty mixed --seed 12345 --actor puzzle-generator
python3 .claude/scripts/ph_cli.py verify <id> --type sudoku

# Artifacts, quality, rights, gates
python3 .claude/scripts/ph_cli.py artifact register <id> <path> --type content --stage CONTENT_GENERATION --actor puzzle-generator
python3 .claude/scripts/ph_cli.py quality evaluate <id>
python3 .claude/scripts/ph_cli.py rights check <id>
python3 .claude/scripts/ph_cli.py approval packet <id> --gate interior

# Builds and packages
python3 .claude/scripts/ph_cli.py build interior <id>
python3 .claude/scripts/ph_cli.py build cover <id>
python3 .claude/scripts/ph_cli.py build digital <id>
python3 .claude/scripts/ph_cli.py build proof <id>
python3 .claude/scripts/ph_cli.py package <id> --channel kdp
python3 .claude/scripts/ph_cli.py package <id> --channel etsy
```

## 9. Safety boundaries

The default framework SHALL NOT:

- submit, publish, unpublish, or change a live listing on KDP, Etsy, Gumroad, or any channel;
- accept platform terms or legal agreements;
- purchase an ISBN or other identifier;
- spend money, launch paid advertising, or change live prices;
- access secrets outside explicitly configured environment variables;
- upload unpublished content to unapproved third-party services;
- treat generated legal analysis as legal advice;
- assert that generated material is copyrightable, original, or cleared without evidence;
- imitate a named living artist or trace a protected image.

`product-submit` records a manual submission or prepares a request. Live connectors require a separately reviewed extension, explicit environment enablement, a valid release authorization, and platform-specific credentials.

## 10. Quality policy

A default final gate requires:

- zero blocker findings;
- zero unresolved major findings;
- every applicable dimension at least 4.0/5;
- solvability, solution correctness, originality, rights, accessibility, and audience fit at least 4.5/5 when applicable;
- weighted overall score at least the configured threshold;
- required deterministic validators (generation, verification, accessibility) passing;
- all rights records cleared or explicitly excluded;
- current approvals bound to current artifact hashes.

Review loops are bounded: three full revision cycles and five targeted repairs per artifact by default. Stagnation or unresolved reviewer conflict escalates to a human.

## 11. MCP

`.mcp.json` exposes a local, read-mostly `publishing-house` server providing state, validation, gate, content-generation, content-verification, and packaging tools. It intentionally exposes no live publishing tool.

Install MCP support with:

```bash
python -m pip install -e '.[mcp]'
```

## 12. Customization

1. Copy `.claude/config/company.default.json` to `.claude/config/company.local.json` and edit publisher details.
2. Review `.claude/config/age_bands.json`, `design_policy.json`, and `quality_gates.json`.
3. Add channel-specific constraints only after rechecking current KDP/Etsy/Gumroad documentation.
4. Keep company secrets outside the repository.

See `ARCHITECTURE.md`, `OPERATOR_GUIDE.md`, `.claude/standards/`, and `.claude/patterns/` for contracts and extension rules.
