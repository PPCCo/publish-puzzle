# STD-RELEASE — Release Contract

Release readiness requires current:

1. content-freeze approval;
2. rights clearance (including originality attestation for all coloring art);
3. accessibility validation;
4. format preflight reports (print and/or digital-PDF);
5. final proof approval;
6. canonical metadata;
7. channel package manifest;
8. release authorization bound to exact hashes.

`packaged`, `ready for submission`, `submitted`, and `published` are distinct states. A successful local build does not imply platform acceptance. Ambiguous external outcomes remain unresolved until reconciled against the platform.

Puzzle products additionally require: verified solvability and solution correctness for all puzzles; answer-key completeness report; difficulty-label accuracy confirmation — all produced by code, not by agent assertion.
